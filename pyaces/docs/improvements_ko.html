A. 정확성과 안정성

1. 모듈별 부분 링크로 고전 빌드와 같은 이름 해석 보장 높음

문제

  • 약 107개 아카이브를 담은 .so 하나를 손으로 쓴 이름 바꾸기 쌍 약 60개(EXTRA_LOCALIZE_SYMBOLS)가 지탱하고 있다.
  • 새 모듈을 넣거나 툴체인이 바뀌면 새 충돌이 생길 수 있고, 감사 기준선에는 이미 알려진 차이가 296개 있다.

제안

  • vcc, vee, lambda 같은 진입 모듈마다 자기 링크 목록(ACES_LINK_LISTS)과 함께 ld -r 로 부분 링크한다. 각 모듈이 고전 실행 파일과 같은 루틴에 연결된다.
  • 그다음 objcopy 로 진입점 외의 심볼을 모두 숨긴다.
  • 이름 바꾸기 목록이 필요 없어지고, 감사 결과도 0에 가까워질 것으로 본다.

주의 — 모듈들이 같은 프로세스 안에서 공유하는 COMMON 블록(/flags/, /icore/ 등)은 전역으로 남겨야 하고, .so 가 커진다. 모듈 하나로 먼저 시험한다.

2. ACES 오류가 Python 인터프리터를 종료시킴 높음

  • aces_exit 가 c_exit 를 불러 프로세스 전체를 끝내므로, Python 이 오류를 잡을 수 없다.
  • “한 프로세스에 계산 하나” 제약도 있으므로, 계산마다 하위 프로세스에서 돌리는 API 계층을 둔다. 테스트 러너(pyaces_suite_runner.py)는 이미 이렇게 한다.

3. COMMON 블록에 연결된 호출 검사 높음

  • 2026-10-23 에 고친 hbar_ 결함(Runhbar 가 lambda 의 COMMON /HBAR/ 을 호출)은 지금 감사 도구가 볼 수 없는 종류다. T hbar_ 가 어디에도 없기 때문이다.
  • pyaces .o 가 부르는 심볼(U)이 .so 에서 데이터(B/D)로 연결되면 빌드를 실패시키는 검사를 추가한다.

4. 이름 바꾸기 실패 시 빌드 중단 높음

  • 지금은 오타가 있거나 처리 대상이 아닌 모듈의 쌍이어도 조용히 무시된다(2>/dev/null || true).
  • 해당 심볼이 그 아카이브에 실제로 있는지, 모듈이 처리 대상인지 확인하고, 아니면 빌드를 실패시킨다.

5. 남은 알려진 결함 중간

  • Getlstpy 가 Irrep, Ndim 인자를 무시하고 Left_index 를 irrep 로 쓴다. 인자를 정리하거나 문서화된 의미에 맞게 고친다.
  • Get1ehpy 의 대칭 블록 오프셋(get1ehpy.F:101)을 대칭이 있는 분자로 검증한다.
  • 러너가 Runpccd 전에 Init() 을 부르는데, Runpccd 는 스스로 Joda 를 부른다. 이 경로는 시험된 적이 없다.

B. 빌드와 컴파일

6. f2py 모듈 이중 생성 제거 중간

  • .pyf 와 소스 스캔이 각각 모듈을 만들고, 두 번째가 첫 번째를 덮어쓴다. 그래서 .pyf 의 intent·COMMON 선언이 적용되지 않는다.
  • 기준을 하나로 정한다: 소스 안의 Cf2py 지시문으로 통일하거나, .pyf 만 쓴다.
  • f2py 의 --lower 옵션으로 sed 소문자 처리 우회를 없앨 수 있다. 다만 Python 함수 이름이 소문자로 바뀌므로 API 가 달라진다.

7. Python 버전 고정 해제 높음

  • 출력 파일 이름이 aces2py.cpython-312-x86_64-linux-gnu.so 로 고정되어 있어 다른 Python 버전에서는 import 되지 않는다.
  • python3 -c "import sysconfig; print(sysconfig.get_config_var('EXT_SUFFIX'))" 결과를 쓴다.

8. 증분 빌드 낮음

  • 빌드할 때마다 gen/ 과 build/ 를 통째로 지우고, 아카이브 약 37개를 다시 푼다.
  • make 나 meson 같은 도구로 단계를 나누면 작은 수정 뒤의 빌드가 훨씬 빨라진다.

9. 컴파일러와 옵션 정리 낮음

  • C 래퍼를 mpicc 로 컴파일하지만 MPI 를 쓰지 않는다. 일반 icx 나 gcc 면 충분하다.
  • Fortran 연결 코드를 -qopenmp 로 빌드하는데, MKL 이 sequential 이라 필요 없을 수 있다. 확인 후 정리한다.

10. 빌드 환경 가정 완화 중간

  • pyaces/build.sh 가 항상 module purge/load 를 하므로, setvars/path 방식 환경이나 module 명령이 없는 곳에서 실패한다. configure 의 ACES_PROGRAM_ENV_MODE 를 따르게 한다.
  • 최상위 build.sh 가 pyaces 의 ifort 셈을 PATH 에 넣기 전에 ifort 를 검사해서, ifx 만 있는 툴체인을 거부한다.

C. 구조 정리

11. 레거시 파일 정리 중간

  • 쓰지 않는 파일(합계 약 47 MB): Fxx/ (45 MB, 약 6,100개 파일), include/, a2_pyf/include_no/, Archive/ 폴더들, Exp/, rename.py.
  • 그 밖에 쓰지 않는 것: 옛 .f 파일 35개, suite_classification.tsv.before_*.
  • 방법: 별도 태그나 브랜치에 남기고 master 에서 지운다. 이력은 그대로 남는다.

12. 헤더 사본 중복 제거 중간

  • Main/*.com 9개는 aces2 헤더와 내용이 다른 옛 사본이다(integer*8 명시, include guard 없음).
  • aces2 헤더를 쓰도록 바꿔 둘이 어긋나지 않게 한다.

13. 이름 바꾸기 목록을 데이터 파일로 분리 중간

  • 약 60쌍과 그 설명이 510줄짜리 스크립트의 주석 속에 묻혀 있다.
  • 한 줄에 한 쌍씩 이유와 함께 적는 데이터 파일(예: tools/localize.txt)로 옮기면, 빌드와 감사 도구가 같은 파일을 읽는다.

14. Python 패키지와 API 계층 중간

  • 지금은 f2py 원시 함수를 그대로 불러야 한다: 대소문자가 섞인 이름, 넘겨준 배열로 받는 결과, 8자로 맞춘 레코드 이름.
  • 소문자 함수, 반환값, 예외, pyproject.toml 을 갖춘 얇은 pyaces 패키지를 둔다. 2번(하위 프로세스 실행)과 함께 설계한다.

15. Python/moio_len.py 수정 낮음

  • 딕셔너리를 "key" = value 로 써서 문법 오류가 나고, 중복 키도 있다.
  • 올바른 딕셔너리 모듈로 고치면 리스트 번호표로 쓸 수 있다.

D. 테스트

16. 테스트 요약 누락과 분류기 문제 높음

  • run_tests.sh 의 pyaces 요약이 MISMATCH 와 TIMEOUT 을 세지 않아, 실패가 요약에서 빠질 수 있다.
  • classify_suite.py 를 다시 돌리면 TSV 에 손으로 고친 행(KS → Runintgrt, 117a/b/c → Rundirmp2, 제외 케이스)이 사라진다. 그 예외들을 코드로 옮긴다.
  • 러너의 기본 실행 디렉터리가 HiPerGator 경로(/blue/...)로 되어 있다.

17. API 단위 테스트 추가 중간

  • 지금은 에너지 값만 검사한다.
  • 레코드 읽기/쓰기, Getreclenpy·Cgetrecpy, Runhbar 의 각 분기, 리스트 접근을 확인하는 작은 테스트를 추가한다.
