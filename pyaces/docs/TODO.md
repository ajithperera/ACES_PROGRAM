### T-01. 모듈별 부분 링크로 고전 빌드와 같은 이름 해석 보장
- **우선순위 / 규모:** 높음 / 큼
- **문제:** 약 107개 아카이브를 담은 `.so` 하나를 손으로 쓴 이름 바꾸기 쌍 약 60개가 지탱한다. 새 모듈이나 툴체인 변경이 새 충돌을 만들 수 있고, 감사 기준선에 알려진 차이가 296개 있다.
- **할 일:** 진입 모듈마다 자기 `ACES_LINK_LISTS`와 함께 `ld -r`로 부분 링크하고, `objcopy`로 진입점 외 심볼을 숨긴다. 공유 COMMON 블록은 전역으로 남긴다. 먼저 모듈 하나(예: vcc)로 시험한다.
- **완료 기준:** 이름 바꾸기 목록 없이 51/51. 감사 차이가 크게 줄어듦. `.so` 크기·빌드 시간 비교 기록.
- **관련 파일:** `pyaces/build.sh`, `aces2/Makefiles/GNUmakefile`(`ACES_LINK_LISTS`)

- **우선순위 / 규모:** 낮음 / 작음

### T-10. 빌드 환경 가정 완화
- **우선순위 / 규모:** 중간 / 작음
- **문제:** `pyaces/build.sh`가 항상 `module purge/load`를 해서 setvars/path 환경에서 실패한다. 최상위 `build.sh`가 `ifort` 셈을 PATH에 넣기 전에 `ifort`를 검사해 ifx만 있는 툴체인을 거부한다.
- **할 일:** configure의 `ACES_PROGRAM_ENV_MODE`를 따르게 하고, `ifort` 검사를 셈 이후로 옮기거나 ifx를 허용한다.

- **관련 파일:** `pyaces/build.sh` (1–17행), `build.sh`(최상위 약 215–225행), `configure`
